# Prototype V0.2 开发任务列表

## 执行规则

- V0.2 必须建立在 V0.1 核心闭环全部通过的基础上。
- 系统深化只能挂载到统一运行时状态，不得绕过核心状态。
- 未在四份交付文档中定义清楚的规则必须记录为缺口，不做成正式业务规则。
- 每个任务完成后必须更新本文档、运行验证、中文提交并推送。

## 任务状态

- [x] Task 1：效果系统
  - 状态：已完成。
  - 范围：效果组、效果定义、目标选择、基础数值操作。
  - 验收：效果必须真实修改运行时状态；未知目标、未知操作、缺失字段必须失败。
  - 验证：
    - `test_effect_system.gd` 通过。

- [x] Task 2：简化政令挂载
  - 状态：已完成。
  - 范围：政令开启、维护费、效果组挂载、资金不足处理。
  - 验收：开启政令必须扣费并真实套用效果；月维护费不足时政令暂停；无效效果不得扣费或记录激活。
  - 验证：
    - `test_policy_system.gd` 通过。

- [x] Task 3：基础外交/谋略入口
  - 状态：已完成。
  - 范围：读取势力状态，执行可校验的停战外交动作与破坏治安谋略动作。
  - 边界：当前只实现 V0.2 入口验证，不扩展正式外交关系网、谋略命中率、反制、情报或事件链规则。
  - 验收：外交/谋略必须校验运行时容器、势力、资金、演员归属和效果目标；失败不得扣费或写入外交/谋略状态。
  - 验证：
    - `test_diplomacy_scheme_system.gd` 通过。
    - `test_save_system.gd` 通过，确认外交/谋略动态状态可存读。

- [x] Task 4：基础 AI 目标选择
  - 状态：已完成。
  - 范围：AI 根据目标归属、路线距离、预计行军天数、粮草需求和外交阻断关系选择可执行进攻目标。
  - 边界：当前只做进攻目标候选筛选与排序，不创建部队、不扣兵粮、不替代出阵/行军/战斗系统。
  - 验收：同势力目标、粮草不足目标、停战/同盟/从属阻断目标不得被选中；有效候选按预计天数、粮草需求、路线 ID 稳定排序。
  - 验证：
    - `test_ai_target_selector.gd` 通过。

## V0.2 当前结论

- 效果系统、简化政令、基础外交/谋略入口、基础 AI 目标选择均已接入统一运行时状态。
- V0.2 仍不是完整外交 AI、完整政略 AI 或完整内容库，只证明扩展系统可以挂载到 V0.1 闭环而不破坏核心状态。
