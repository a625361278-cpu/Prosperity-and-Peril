# 《三国志：治世与乱世》项目说明

## 项目定位

本项目是一个三国题材大型单机历史战略游戏工程。当前阶段不是复刻任何现有作品，而是把 `E:\newsanguo` 下四份交付文档中的系统设计、数据结构和验收标准转化为可执行的 Godot 工程。

## 最高需求源

以下四份文档是当前唯一需求基础：

- `三国志_治世与乱世_理论企划案_V1.0.docx`
- `三国志_治世与乱世_数据母表_V0.3.xlsx`
- `三国志_治世与乱世_完整策划开发需求文档_2026-06-05.docx`
- `三国志_治世与乱世_完整需求索引与验收矩阵_2026-06-05.xlsx`

实现时必须遵循这些文档中的玩法边界、字段定义、状态流转、数据表、公式方向和 QA 验收项。文档没有写清楚的内容不得直接做成正式业务规则；必须记录为缺口或待确认事项。

## 引擎与工具

- 引擎：Godot 4.6.2 stable
- Godot 路径：`F:\godot\Godot_v4.6.2-stable_win64.exe\Godot_v4.6.2-stable_win64.exe`
- 当前目标：先完成正式原型路线和 Prototype V0.1 实施计划，再逐版本实现。

## 当前工程状态

当前工程已完成 Prototype V0.1 核心闭环，并正在推进 Prototype V0.2 系统深化。V0.1 已跑通：

城市 -> 任命 -> 出阵 -> 行军 -> 粮草 -> 接敌 -> 战斗 -> 占领 -> 战后整合 -> 存档读档

V0.2 已接入效果系统、简化政令、基础外交/谋略入口、基础 AI 目标选择。当前实现仍属于原型验证，不代表完整正式外交、谋略、AI 或内容库规则已经定稿。

Prototype V0.2.1 开始建立编辑器可见切片：主场景会显示测试数据驱动的 3D 战略地图、城池、路线、部队标记和调试面板。该阶段用于确认系统状态能被真实渲染，不等同于 Beta/正式版 UI。

Prototype V0.3 已开始挂载三国特色规则。当前已接入势力正统/名望基础状态、城市士族支持、人物关系/武将忠诚/降将状态、关隘/水路通行入口、变化日志、存档恢复和调试面板展示；官爵、诏令、称帝路线、完整士族事件链、完整叛逃策反和完整水战仍未实现。

Prototype V0.3.1 开始把 V0.3 已有战略地理状态转成更清楚的编辑器可见表达：普通道路与关隘路线可区分，敌方阻断关隘会显示阻断标记，城市/部队可以被点击选择，右侧调试面板加入可读宽度约束和当前选择详情。该阶段仍不代表完整三国地图、完整内容库或 Beta 正式 UI。

Content Alpha 已开始建立内容库与 UI 原型的前置入口。当前已完成英雄半身像候选资源索引、项目内导入、运行时 `res://` 加载、`.pck` 打包烟测、212 张可复用半身像池、头像绑定候选武将名册、候选选择状态导出工具、独立半身像浏览组件、候选武将名册浏览组件、Content Alpha 资源工作台及主场景调试入口、UI 信息架构规格和工作台浏览入口、正式 UI 风格方向图、正式 UI 线框规格和工作台浏览入口、正式 UI 主题 Token 和工作台浏览入口，以及调试面板中的图池预览和可见校验摘要。半身像来自项目负责人另一个自有三国项目，只作为视觉资源复用；源项目技能、传记、君略、官职、势力和数值不进入本项目数据。候选名册不是正式武将库，最终武将库可以只覆盖有可复用半身像的约 200 名武将，不强行补齐没有半身像的角色。UI 信息架构、线框规格、主题 Token 和风格方向只声明后续正式界面的设计基准，不代表 Beta 正式 UI 已完成。

## 执行原则

- 不伪造业务结果。
- 不用 fallback 假数据掩盖缺表、缺资源、缺字段。
- 不静默吞异常。
- 不用兼容逻辑隐藏文档冲突或状态机错误。
- 异常状态优先暴露并定位原因。
- 业务设计如需调整，必须说明原因、影响和副作用，并同步更新本文档或相关计划文档。
