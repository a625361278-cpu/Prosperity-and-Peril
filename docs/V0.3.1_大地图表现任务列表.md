# Prototype V0.3.1 大地图表现任务列表

## 执行规则

- 本版本只改进 V0.2.1/V0.3 已有运行时状态的大地图表达，不新增正式业务规则。
- 地图内容仍使用测试数据，不伪装成完整三国地理内容库。
- 路线、关隘、通行阻断等显示必须来自真实状态字段，不得用假图标或默认值掩盖缺字段。
- UI 调试面板仍属于原型调试入口，不等同于 Beta/正式版 UI。
- 每个任务完成后必须运行验证、中文提交并推送。

## 需求来源

- 企划案：`13_野战_攻城_关隘与水战`，要求关隘、水路等战略地理结构参与战争表达。
- 完整开发需求文档：`DEV_关隘_港口_水路战需求说明`，要求关隘/水路作为路线与战斗触发入口。
- 数据母表：`battle_rules.battle_type=pass/port/river`，以及当前测试数据 `routes.route_type / strategic_node_type / blocks_enemy_passage`。
- 需求索引：M3 `三国特色挂载`，要求关隘水路不只作为文本字段，而要作为可验证规则入口。

## 任务状态

- [x] Task 1：路线类型可视化
  - 状态：已完成。
  - 范围：大地图渲染普通道路、关隘路线时写入路线类型元数据，并用不同颜色和偏移避免重叠路线完全覆盖。
  - 边界：不制作正式地形、不制作完整全国路线网、不制作港口/水路美术。
  - 验收：缺少 `route_type` 或遇到不支持路线类型必须失败；同起终点的普通道路与关隘路线必须可区分。
  - 验证：`test_strategic_map_view.gd` 通过。

- [x] Task 2：关隘阻断标记
  - 状态：已完成。
  - 范围：当路线真实状态包含 `blocks_enemy_passage=true` 时，在对应关隘路线中生成阻断标记。
  - 边界：不实现正式关隘模型、不实现关隘战 UI、不改变 V0.3 通行规则。
  - 验收：阻断标记必须由真实路线字段驱动，不能静默替换或默认生成。
  - 验证：`test_strategic_map_view.gd` 通过。

- [x] Task 3：调试面板可读布局
  - 状态：已完成。
  - 范围：把运行时状态文本放入右侧固定最小宽度面板，避免窗口下出现文字竖排。
  - 根因：原调试面板只有裸 `Label` 和弱宽度约束，自动换行在当前窗口布局下被压成窄列。
  - 副作用：右侧面板会占用更多屏幕宽度；这符合当前调试阶段目的，Beta 前会替换为正式 UI。
  - 验证：`test_debug_panel_layout.gd` 通过。

- [x] Task 4：城市/部队点击选择与当前选择面板
  - 状态：已完成。
  - 范围：大地图为城市与部队生成真实 `Area3D` 命中区域，选中后发出实体类型和 ID，右侧面板从运行时状态显示对应城市或部队详情。
  - 边界：不实现正式城市菜单、不实现出阵按钮流、不实现部队命令菜单，不把调试面板包装成 Beta 正式 UI。
  - 验收：城市/部队命中区域必须携带真实实体元数据；未知城市或未知部队选择必须失败；选择详情必须来自 `state.cities` / `state.armies`，不能从显示文本反推。
  - 验证：
    - `test_strategic_map_view.gd` 通过，确认城市/部队可选节点与选择信号。
    - `test_debug_state_presenter.gd` 通过，确认城市/部队选择详情和缺失实体失败。
    - `test_debug_panel_layout.gd` 通过，确认右侧面板存在独立当前选择区域。

## 当前结论

- 当前运行主场景时，编辑器/运行窗口可以看到更清楚的 3D 战略地图原型：城池、普通道路、关隘路线、阻断标记、部队和右侧状态面板。
- 当前运行窗口中可以点击城市或部队，右侧面板会显示被选中对象的真实运行时详情。
- 本版本仍不是 Content Alpha 完整内容库，也不是 Beta 正式 UI；它是进入正式大地图原型前的可见表达基础。

## 当前缺口

- 城池坐标仍为测试坐标，尚未从正式地图数据表导入。
- 正式中国地形、州郡边界、关隘港口水路清单尚未建立。
- 正式城市菜单、部队命令面板、信息面板美术风格仍待后续 Content Alpha/Beta 阶段。
