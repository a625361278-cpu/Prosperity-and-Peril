第 01 章  《三国志：治世与乱世》项目说明
状态：Draft V0.1
阶段：原创企划启动
用途：说明本目录与《信长之野望：新生》竞品拆解目录之间的关系。
一、项目定位
《三国志：治世与乱世》是一个三国题材大型单机历史战略游戏企划项目。
本项目不以复刻任何现有作品为目标，而是以《信长之野望：新生 / 威力加强版》的系统拆解成果为参考，提炼其可迁移的核心策略骨架，并在三国题材下重新设计世界结构、制度表达、人物关系、战争方式、事件逻辑和数值内容。
核心设计方向：
乱世中夺地、用人、建制；
治世中安民、养将、立法；
最终从一方诸侯走向天下秩序。
二、与竞品拆解目录的关系
竞品拆解目录：
01_企划案/04_竞品拆解_信长新生/
负责回答：
《新生》的核心循环是什么。
《新生》的系统如何互相连接。
《新生》的任命、内政、政策、军事、战斗、AI、数据表如何组织。
哪些系统结构适合迁移到三国题材。
当前原创企划目录：
01_企划案/05_原创企划_三国志治世与乱世/
负责回答：
三国题材下应该保留哪些核心玩法。
原作系统应该如何改名、改义、改结构。
哪些系统必须因三国时代而新增。
最终如何形成可交给程序、美术、策划、数值策划开工的正式企划案。
三、设计边界
本项目保留的是“玩法骨架”和“策略关系”，而不是原作的具体表达。
可以参考和迁移：
大地图势力扩张的主循环。
人事任命驱动地方治理。
城池职责化与区域经营。
制度、政策、官职形成长期构筑。
武将能力、特技、战法、岗位形成搭配。
战争准备、补给、行军、会战、攻城的闭环。
大势力后期通过军团和委任降低管理压力。
必须重新设计：
系统命名。
三国时代制度表达。
地图尺度与城池结构。
武将、士族、宗族、旧主、姻亲关系。
战法、特技、政策、官职、事件文本。
城池、郡县、关隘、港口、渡口、道路网络。
数值表、公式参数和数据库内容。
UI 呈现和美术资产。
四、阶段目标
V0.1 三国化转换总纲
建立从《新生》系统到《三国志：治世与乱世》系统的转换原则。
V0.2 系统企划目录
拆出正式企划案章节，明确每章要产出的规则、数据表和验收项。
V0.3 核心循环与设计支柱
定义游戏的第一版核心体验、核心循环、玩家决策层级和胜利目标。
V0.4 系统分章初稿
逐章完成世界结构、人事、内政、政策、军事、战斗、外交、AI、数据结构。
V1.0 可评审企划案
形成可转 Word 的系统企划案正文，并同步整理可转 Excel 的数据母版。
第 02 章  《三国志：治世与乱世》三国化转换总纲
状态：Draft V0.1
阶段：原创企划启动
参考基础：《信长之野望：新生 / 威力加强版》系统拆解成果
用途：定义从竞品系统骨架到三国题材原创企划的转换原则。
一、核心结论
《三国志：治世与乱世》不应被定义为简单“换皮”。
更准确的定位是：
以《新生》式历史大战略系统为参考，
在三国题材下重构一套以人事、州郡、制度、战役和天下秩序为核心的原创企划。
本项目应保留《新生》的核心策略价值：
玩家不是逐项执行所有细节，而是通过任命、制度、目标和关键战役驱动势力机器。
人才不是静态卡片，而是治理、战争、谋略、外交、制度构筑的核心资源。
城池不是同质产出点，而是可被塑造成不同职责的战略节点。
政策不是简单科技树，而是有成本、有条件、有路线取舍的国家制度。
战争不是点选出兵，而是由目标、军备、补给、道路、行军、会战和攻城组成的连续过程。
一场关键战役应能改变地区局势，而不是只消耗一支部队。
但三国化时必须重构表达：
日本战国的大名家臣制
→ 汉末三国的诸侯、汉室、州郡、士族、军府、宗族和名分政治
二、顶层设计母题
内部项目名为：
《三国志：治世与乱世》
该标题可以拆成两条核心体验线：
1. 乱世线
玩家在乱世中面对：
群雄割据。
城池争夺。
诸侯外交。
关隘攻防。
粮道压力。
降将反复。
天子名分。
军师谋略。
关键战役。
乱世线强调扩张、博弈、战争和机会。
2. 治世线
玩家在治世中处理：
州郡治理。
郡县开发。
屯田安民。
士族关系。
人才任命。
官制建设。
民心恢复。
战后整合。
制度升级。
治世线强调经营、秩序、人才和长期制度。
3. 总体验
游戏的核心体验应是：
在乱世中建立秩序，
用秩序支撑更大的战争，
再用战争打开新的治世空间。
三、核心循环转换
《新生》的主循环：
观察局势
→ 任命家臣
→ 治理城郡
→ 制定政策和评定众
→ 指定攻略目标
→ 军备、调略、补给准备
→ 行军、合战、攻城
→ 触发威风或占领
→ 获得功勋、领土、资源
→ 论功行赏、恩赏、重组领地
→ 进入下一轮扩张
三国化后的主循环建议为：
观察天下大势
→ 任命太守、都督、属官和军师
→ 治理州郡、发展城邑、安抚民心
→ 颁行政令、调整官制、经营士族与汉室名分
→ 设定征讨目标或外交目标
→ 筹粮、募兵、整军、计略、补给准备
→ 行军、野战、攻城、关隘战、水陆协同
→ 形成声势、归附、震慑或占领
→ 获得土地、人口、军资、功绩和名望
→ 封赏、升迁、安置降将、重组战区
→ 进入下一轮治世与乱世循环
设计重点
三国化后，循环必须更强调：
名分：汉室、诏令、正统、称王称帝、禅让。
人心：民心、士族、降将、旧主关系。
地势：关隘、渡口、山道、水系、粮道。
战区：州牧、太守、都督、军府。
谋略：离间、策反、火攻、伏兵、伪报、劝降。
四、三层玩法结构转换
《新生》的三层结构为：
宏观层：势力战略
中观层：城郡治理
微观层：武将与战斗
《三国志：治世与乱世》建议改写为：
天下层：大势、名分、外交、战略方向
州郡层：州、郡、城、关、港、道路、粮道
人物层：君主、文臣、武将、军师、士族、宗族、降将
1. 天下层
玩家关注：
哪个诸侯正在坐大。
汉室天子在谁手中。
是否奉诏、讨逆、称王、称帝。
和哪些势力结盟、停战、联姻、从属。
政令路线是屯田、军制、法治、士族、寒门还是霸府。
哪个方向是下一阶段主攻路线。
对应系统：
君主与势力。
汉室与正统。
外交与联盟。
政令与官制。
势力目标。
军团 / 都督府。
AI 天下局势判断。
2. 州郡层
玩家关注：
哪些城是前线重镇。
哪些郡县负责粮草、兵源、商业、军工。
哪些关隘和渡口决定攻防路线。
哪些城市适合设为都督府、补给节点、防卫重镇。
哪条粮道支撑远征。
新占领地区如何恢复民心和秩序。
对应系统：
州郡地图。
城池与郡县治理。
城市职责。
设施与开发。
粮道与补给。
防线、关隘、港口、渡口。
战区委任。
3. 人物层
玩家关注：
谁适合当太守。
谁适合做都督。
谁适合担任军师或中枢官职。
谁适合驻守边境。
谁适合治理新占地区。
谁是宗族核心、派系领袖、降将风险、士族代表。
哪些武将组合能形成政策、战法或战区流派。
对应系统：
武将能力。
特技、战法、军师技。
忠诚、野心、义理、名望。
宗族、旧主、姻亲、同乡、士族关系。
官职、爵位、封赏。
功绩与升迁。
降将安置。

六、必须新增的三国特色系统
1. 汉室与正统系统
三国题材不能只有领土扩张，还需要名分政治。
建议设计：
汉室天子作为特殊政治资源。
控制天子可获得诏令、官爵、名分、外交压力。
过度挟天子可能引发反感、讨伐、忠汉派不满。
称王、称帝、禅让应成为中后期重大路线选择。
策略价值：
给中原势力独特优势和风险。
给弱势势力制造“奉诏讨逆”的外交空间。
让统一不只是军事胜利，也包括政治合法性。
2. 士族、豪强与民心系统
三国地方治理离不开士族和豪强。
建议设计：
每个州郡有士族影响、民心、豪强稳定度。
新占领地区需要安抚或清洗。
高政治、高魅力武将适合治理复杂地区。
士族支持可提高人才、收入、治安。
士族不满可能导致叛乱、出仕减少、降将不稳。
策略价值：
让战后治理成为真实成本。
让文官和名望型武将有长期价值。
避免玩家只靠连续战争滚雪球。
3. 宗族、旧主与降将系统
三国人物关系强于日本战国通用家臣结构。
建议设计：
武将有宗族、旧主、同乡、姻亲、师友、宿敌关系。
降将忠诚不只看赏赐，还看旧主存亡、关系网络、名分路线。
宗族核心可稳定同族武将，也可能形成派系。
重用降将可能引发旧臣不满。
策略价值：
强化人物戏剧性。
让人才收编成为政治决策。
让“人和”成为系统而非口号。
4. 州牧、太守、都督的行政层级
三国化不能只用“城主-领主”二层。
建议层级：
君主
→ 中枢官职
→ 都督 / 州牧
→ 太守
→ 县令 / 属官 / 校尉 / 从事
设计原则：
前期小势力可以只管少量城池。
中期通过州牧、太守管理地方。
后期通过都督府进行战区委任。
官职不仅是称号，还影响管辖范围、政策权限和忠诚。
5. 关隘、水路与粮道系统
三国战争地理特征非常强。
建议重点：
北方平原适合骑兵机动和大军会战。
荆扬地区强调水系、港口、船坞、水军。
巴蜀强调山道、剑阁、粮道、险关。
关中强调潼关、函谷、武关等战略门锁。
江淮强调合肥、寿春、濡须等水陆交界。
策略价值：
让地图本身产生流派。
让城池数量之外，路线和节点更重要。
让三国著名战区自然形成。
6. 军师与谋略系统
三国玩家期待军师有强存在感。
建议设计：
军师可进入中枢、战区或部队。
军师提供计略、战前判断、战场战法、外交建议。
高智谋军师可执行离间、伪报、火攻、伏兵、劝降。
军师与主将组合影响战斗策略上限。
策略价值：
把诸葛亮、郭嘉、荀攸、贾诩、周瑜、陆逊等人的价值系统化。
让智谋型武将不只是内政数值。
强化战前塑形，而不是只在战场点技能。

制度路线有持续成本。

战争需要战前准备。

城下设施不直接使用，应改为城邑设施、军府设施、屯田设施。
二名不直接使用，应改为威名、称号、霸业称谓。
主義不直接使用，应改为施政路线或政治倾向。

士族、豪强、民心。
宗族、旧主、姻亲。
降将安置。

水战、关隘、渡口。
军师与计略。
历史事件链与改史分支。
4. 暂缓到后期的内容
全剧本城池归属。
全武将出生死亡和登场位置。
全历史事件触发条件。
具体地图坐标。
精确战斗公式。
全量数值平衡。
这些内容在系统骨架稳定后再做，否则会过早陷入资料泥潭。

第 04 章  《三国志：治世与乱世》项目总纲
状态：Draft V0.1
阶段：原创企划
用途：定义游戏定位、核心体验、目标用户、设计边界和首版范围。
一、项目一句话定义
《三国志：治世与乱世》是一款三国题材大型单机历史战略游戏。
玩家扮演汉末三国时代的一方势力之主，通过任命人才、治理州郡、建设制度、经营名分、筹粮整军、指挥战役和整合新领土，在乱世中扩张势力，并最终建立新的天下秩序。
核心体验可以概括为：
以人为本，以城为基，以粮为限，以势破局，以制度定天下。
二、项目定位
1. 类型定位
游戏类型：
大地图历史战略。
单机沙盘模拟。
势力经营。
人才任命。
战争准备与关键战役。
数据驱动的长期养成。
本项目不是纯战棋、纯即时战斗、纯卡牌养成或剧情 RPG。
玩家的主要身份不是单个武将，而是一方势力的最高决策者。
2. 体验定位
本项目强调：
看懂天下局势。
用合适的人治理合适的地方。
把城池、人口、粮草、士族和制度转化为战争能力。
通过道路、关隘、港口、渡口和粮道决定进攻路线。
在关键战役中获得超出一城一地的战略成果。
战后重新分配官职、土地、封赏和战区。
玩家应始终感到：
战争不是从出兵按钮开始，
而是从多年经营、任命、屯田、修路、外交和谋略开始。
3. 题材定位
本项目使用三国题材，但重点不是复述固定剧情。
题材重点包括：
汉室衰微与名分政治。
群雄割据与诸侯争霸。
州郡治理与地方豪强。
宗族、士族、旧主、姻亲和降将关系。
北方骑兵、江淮水陆、巴蜀山道、关中险关等地理差异。
军师谋略、战前塑形和关键会战。
从乱世军事集团走向治世国家机器。
三、目标用户
1. 核心用户
核心用户是喜欢大型历史战略游戏的玩家。
他们通常重视：
长局体验。
沙盘变化。
历史人物。
地图战略。
数据成长。
内政与战争联动。
高自由度改史。
2. 次级用户
次级用户包括：
喜欢三国题材但不满足于轻度手游的玩家。
喜欢武将搭配、政策构筑和数值研究的玩家。
喜欢经营、委任、AI 沙盘演化的玩家。
喜欢以弱胜强、外交破局、战略布局的玩家。
3. 不优先服务的用户
首版不优先服务：
只想快速抽卡养成的玩家。
只想玩线性剧情的玩家。
只想手操每场战斗、忽略内政的玩家。
只接受轻量 10 分钟一局体验的玩家。
四、核心卖点
1. 治世与乱世双循环
游戏不是只强调扩张，也不是只强调内政。
治世提供：
民心。
人口。
粮草。
财政。
士族支持。
人才稳定。
制度效率。
乱世消耗：
兵力。
粮草。
金钱。
忠诚。
民心。
外交信用。
战争打开新领地，新领地需要治理；治理产生新资源，新资源支撑更大规模战争。
2. 人事即经营
玩家的核心决策不是逐项点击每座城的所有建设，而是任命：
太守。
属官。
军师。
都督。
中枢官职。
前线守将。
后方治理官。
武将价值由能力、特技、关系、忠诚、身份、官职和岗位共同决定。
3. 城池职责化
每座城不是简单的收入点，而应被塑造成不同战略职责：
州治。
前线重镇。
粮仓。
商都。
军府。
马政中心。
船坞港城。
关隘防线。
转运粮站。
新占恢复区。
城市职责决定设施、驻将、兵力、粮草、道路和战区价值。
4. 制度构筑
玩家通过政令、官制和中枢官职建立势力路线。
可能路线包括：
屯田强国。
军府扩张。
士族共治。
法治集权。
霸府挟天子。
汉室正统。
水军江东。
骑兵北方。
山地固守。
制度应有持续成本和代价，避免成为无脑科技树。
5. 战争准备比出兵更重要
部队从城池出阵，受城池兵力、武将能力、军备状态、兵粮、道路、补给和行军时间影响。
军事系统必须保留以下体验：
城池提供部队
部队携带粮草
行军消耗时间
路线决定风险
补给决定远征上限
关键战役决定地区走势
6. 关键战役改变地区局势
本项目不希望所有扩张都变成机械的一城一城推进。
当玩家在重要地点取得大胜时，应可能引发：
周边敌城动摇。
地方豪强倒戈。
敌方降将归附。
敌势力士气下跌。
中立势力重新站队。
己方名望提升。
该系统暂名为：
声势系统
五、核心设计支柱
1. 天时：名分、时机与天下大势
天时代表：
汉室正统。
诏令和官爵。
诸侯关系。
天下局势。
战争窗口。
灾荒、叛乱和事件。
称王称帝时机。
玩家需要判断什么时候该忍、什么时候该攻、什么时候该奉诏、什么时候该自立。
2. 地利：城池、关隘、道路与粮道
地利代表：
州郡城池。
关隘。
港口。
渡口。
山道。
水路。
补给节点。
战区纵深。
玩家需要通过地形和补给设计战争，而不是只堆兵力。
3. 人和：人才、关系、士族与民心
人和代表：
武将任命。
宗族关系。
旧主关系。
士族支持。
民心治安。
忠诚野心。
降将安置。
官职封赏。
玩家需要让人愿意为自己治理、作战和守成。
4. 制度：把势力变成国家机器
制度代表：
政令。
官制。
中枢府署。
都督府。
屯田。
军制。
法度。
选官。
制度是从乱世集团走向治世国家的关键。
5. 战役：以关键胜利撬动大局
战役代表：
征讨目标。
战前整军。
行军协同。
野战。
攻城。
关隘战。
水陆协同。
战后声势。
战役的价值不是单场胜负，而是改变地区格局。
六、玩家身份
玩家扮演一个势力的最高统治者。
根据剧本和势力不同，玩家可能是：
汉臣。
州牧。
太守。
诸侯。
权臣。
王。
皇帝。
玩家不直接扮演单个武将进行 RPG 式成长。
但君主本人也是武将对象，具有：
能力。
特技。
施政倾向。
名望。
官爵。
亲族。
关系网。
君主能力和路线会影响势力可用政策、人才忠诚、外交态度和名分选择。
七、游戏目标
1. 最终目标
标准胜利目标：
统一天下，并建立被主要政治力量承认的新秩序。
统一不应只等于占领全部城池。
还应包含：
消灭或臣服主要敌对势力。
拥有足够正统或名望。
完成称帝、禅让、复汉或改朝路线之一。
稳定核心州郡。
维持足够民心和财政。
2. 阶段目标
游戏应提供阶段性霸业目标，例如：
立足一州。
控制州治。
迎奉天子。
平定河北。
入主中原。
坐断江东。
入蜀称王。
夺取关中。
北伐中原。
三分归一。
阶段目标用于引导玩家，不应强制锁死玩法。
3. 势力特色目标
不同势力可有特色目标。
示例：
曹操：奉天子以令诸侯，平定中原，统一北方。
刘备：匡扶汉室，入主益州，联吴抗曹，北伐中原。
孙权：稳固江东，夺取荆扬，建立水军霸权。
袁绍：压制公孙，统一河北，南下官渡。
董卓：控制天子，压服关东，稳定关中。
这些目标应提供奖励和方向，但允许玩家改史。
八、首版范围建议
1. 首版必须包含
首版系统应包含：
势力与君主系统。
州郡城池地图。
太守、属官、都督、中枢官职任命。
城池开发与城市职责。
民心、粮草、金钱、兵力。
政令与官制。
武将能力、特技、战法。
征讨目标、整军、出阵、行军、补给。
野战和攻城的基本规则。
外交基础。
谋略基础。
声势与战后整合。
基础 AI 势力行为。
2. 首版可以简化
首版可以简化：
水战先做为水路行军和港口战加成，不必一开始做完整独立战斗模式。
汉室系统先做名分、官爵、诏令和称帝路线，不必一开始做复杂朝廷模拟。
士族系统先做州郡支持度和人才影响，不必一开始模拟全族谱政治。
历史事件先做关键事件链，不必覆盖全部年份。
战斗可以先实现规则骨架，再逐步增强战场表现。
3. 首版暂缓
首版可暂缓：
全量历史事件。
全剧本全武将精确登场。
复杂水军战场。
细粒度人口迁徙。
完整官僚派系斗争。
大量个人剧情。
多结局演出。
九、差异化原则
1. 与传统三国 SLG 的差异
本项目重点不只是：
更多武将。
更多城市。
更多战法。
更多事件。
而是强调：
人事驱动经营。
州郡职责化。
战争准备链。
名分和人心。
制度路线。
战后整合。
大势力委任和 AI 沙盘。
2. 与《新生》的差异
本项目不直接使用《新生》的系统命名和题材表达。
关键差异：
日本战国大名制改为汉末州郡、诸侯、汉室和士族结构。
城郡知行改为太守、属官、都督、封邑和州郡治理。
家宰奉行改为中枢官职和府署。
威风改为声势、震慑和归附。
铁炮兵种路线改为三国的骑兵、水军、弩兵、攻城、山地等路线。
名胜和二名改为古迹、险关、威名、霸业称号。
十、企划完成标准
本项目企划案达到 V1.0 时，应能回答：
玩家每个月做什么。
玩家为什么要任命某个武将到某个岗位。
一座城如何从普通城变成粮仓、军府或重镇。
政令为什么有取舍，而不是全都开。
一场战争从准备到战后的完整流程是什么。
军粮、行军时间、道路和补给如何影响胜负。
三国的汉室、士族、宗族、降将如何进入系统。
AI 势力如何扩张、外交、任命和作战。
程序需要哪些数据库表。
数值策划需要配置哪些字段和公式。
QA 如何判断一个系统是否完成。
第 05 章  《三国志：治世与乱世》核心循环与设计支柱
状态：Draft V0.1
阶段：原创企划
用途：定义游戏主循环、玩家决策层级、治世循环、乱世循环和系统设计支柱。
一、核心判断
《三国志：治世与乱世》的核心体验不是“每回合手动点完所有城池”，也不是“只靠名将堆兵力横推”。
本项目的核心体验应是：
玩家通过任命、制度、地理、粮道、外交和关键战役，
驱动一套由人才与州郡构成的势力机器。
玩家的主要乐趣来自五类判断：
天下局势是否允许扩张。
哪些人应该被放到哪些岗位。
哪些城应该承担哪些职责。
哪条路线有足够粮草和时间支撑。
哪场战役值得投入主力以撬动地区局势。
二、主循环
建议主循环如下：
观察天下大势
→ 调整人事与战区
→ 治理州郡与城市职责
→ 颁行政令与经营名分
→ 设定征讨或外交目标
→ 筹粮、募兵、整军、计略
→ 出阵、行军、补给、接敌
→ 野战、攻城、关隘战或水陆战
→ 形成声势、占领、归附或停战
→ 封赏、升迁、安置降将、恢复民心
→ 重组领土和战区
→ 进入下一轮治世与乱世循环
这个循环分为三个连续阶段：
治世准备
→ 乱世突破
→ 战后整合
其中战后整合会重新回到治世准备。
三、治世循环
治世循环负责把领土转化为长期能力。
任命太守和属官
→ 建设城邑和设施
→ 恢复民心与治安
→ 发展农业、商业、屯田和军工
→ 稳定士族、豪强和降将
→ 颁行政令、升级官制
→ 积累金钱、粮草、兵力、名望和人才
→ 支撑下一次扩张
1. 治世循环的输入
治世循环的输入包括：
已有城池。
新占领地区。
武将和文臣。
金钱。
粮草。
人口。
士族支持。
民心状态。
官职和制度权限。
2. 治世循环的输出
治世循环的输出包括：
金钱收入。
军粮储备。
兵力和募兵速度。
城防和设施。
城市职责。
武将功绩。
忠诚稳定。
政令维持能力。
战争准备速度。
3. 治世循环的压力
治世不是纯收益系统，必须有压力：
新占领地区民心低。
士族可能不合作。
豪强可能叛乱。
降将可能不稳。
开政策有持续财政成本。
抽调前线兵力会削弱本地安全。
过度征兵和征粮会伤害民心。
4. 治世循环的玩家问题
玩家应持续思考：
这个新占城池是直接军事化，还是先恢复民心。
高政治文官应该放在中枢还是地方。
前线城应该优先粮草、兵力还是防御。
是否为了快速开战而牺牲长期发展。
是否重用当地降将安抚地方。
是否迁移治所或设立都督府。
四、乱世循环
乱世循环负责把治世成果转化为战争成果。
选择征讨目标
→ 判断道路、关隘、水路和粮道
→ 前线城整军
→ 军师和谋士执行计略
→ 多城部队出阵
→ 部队携带随军粮草
→ 大地图按时间行军
→ 接敌、截击、包围或攻城
→ 关键战斗
→ 形成声势或占领
1. 乱世循环的输入
乱世循环的输入包括：
出阵城兵力。
指挥武将。
军师和战法。
城市军备状态。
随军粮草。
道路和地形。
补给节点。
外交关系。
敌方守军和援军。
2. 乱世循环的输出
乱世循环的输出包括：
敌军损失。
城池占领。
地区声势。
敌城动摇。
敌将归附。
武将功绩。
名望提升。
新前线形成。
战后治理压力。
3. 乱世循环的压力
乱世循环必须受到约束：
部队从具体城池出阵。
出阵会抽空本城兵力。
部队携带粮草有限。
大地图移动需要时间。
移动速度受道路、地形、状态和部队类型影响。
远征需要补给节点。
多路协同需要时间差判断。
长期战争会消耗民心、财政和外交信用。
4. 乱世循环的玩家问题
玩家应持续思考：
是否等前线城完成整军再出兵。
哪些城出兵，哪些城留守。
主力是否能在粮草耗尽前抵达目标。
是否需要先夺关隘、港口或渡口。
是否通过计略削弱敌城再攻。
是否用偏师牵制援军。
是否追求大胜声势，还是稳妥占城。
五、战后整合循环
战后整合是本项目避免无脑滚雪球的关键。
占领或归附
→ 接收城池、人口、俘虏和降将
→ 判断民心、士族、豪强和治安
→ 任命太守、属官和守将
→ 封赏功臣
→ 安置降将
→ 修复城防和设施
→ 调整前线与后方
→ 决定继续进攻或转入治理
1. 战后整合的策略价值
战后整合让战争成果不是免费获得。
玩家需要处理：
谁来治理新城。
谁来镇守边境。
降将是否可信。
当地士族是否支持。
民心是否足够继续征粮。
是否把新城设为前线军府或恢复区。
是否继续追击导致后方不稳。
2. 战后整合的失败后果
如果玩家忽视整合，可能导致：
民心下降。
叛乱。
降将逃亡。
收入下降。
补给不足。
士族人才不出仕。
前线被反攻。
六、时间结构
1. 基础时间单位
建议采用月为主要政略单位。
每月处理：
收入。
粮草。
政令维护费。
城市发展。
武将任务推进。
外交和谋略进度。
军备进度。
AI 势力行动。
2. 大地图实时或半即时推进
行军和战争应在大地图时间中推进。
关键规则：
部队出阵后在大地图移动。
移动需要时间。
路线由道路、水路、关隘、渡口决定。
部队有移动速度。
行军消耗随军粮草。
接敌后进入自动接触战、可选会战或攻城流程。
3. 季节和年份
季节可以影响：
农业收入。
粮草收获。
雨季行军。
冬季消耗。
水位和水战。
灾害和流民。
首版可先实现基础季节收益和少量事件，不必一开始做复杂气候模拟。
七、玩家决策层级
1. 天下层决策
玩家决定：
下一阶段战略方向。
与谁结盟、停战、从属或开战。
是否奉诏、讨逆、称王、称帝。
采用哪条政令路线。
是否迁都或迁治所。
是否设立都督府。
天下层决策影响长期格局。
2. 州郡层决策
玩家决定：
哪座城作为州治或战区核心。
哪座城作为前线重镇。
哪座城作为粮仓、商都或军府。
哪些关隘和渡口必须控制。
哪些城市负责补给。
新占地区如何治理。
州郡层决策影响资源和战争可执行性。
3. 人物层决策
玩家决定：
谁当太守。
谁做属官。
谁做都督。
谁做军师。
谁进入中枢。
谁带兵出阵。
谁获得封赏。
谁被安置到新占地区。
人物层决策影响效率、稳定和组合流派。
4. 战役层决策
玩家决定：
从哪些城出兵。
走哪条路线。
带多少兵和粮。
是否等待整军完成。
是否多路协同。
是否诱敌、截击、围城或强攻。
是否主动进入会战。
战役层决策影响短期胜负和地区声势。
八、设计支柱
1. 人事驱动
原则：
玩家通过任命改变城市、战区和制度效率。
每个重要岗位都应回答：
需要什么能力。
需要什么身份或官职。
对哪个系统生效。

第 06 章  《三国志：治世与乱世》世界结构与地图规则

第 07 章  《三国志：治世与乱世》君主、势力与汉室正统

解锁高级官职。

复兴汉室。
称帝效果：
进入最终统一阶段。
解锁最高制度。
提高正统结算要求。
可能触发天下联盟或降服潮。
十、AI 行为

曹操型 AI 倾向控制天子、奉诏扩张。
刘备型 AI 倾向提高汉室正统和民心。
孙权型 AI 倾向区域割据后称王。
袁绍型 AI 倾向依靠名门和河北实力称霸。
董卓型 AI 倾向高压控制天子但引发反弹。
AI 称王称帝不能只看城池数量，还应看：
周边敌我实力。
正统风险。
是否容易被围攻。
内部稳定。
外交环境。

本项目的核心不是玩家手动执行所有事务，而是通过任命人才驱动势力机器。
人才与任命系统要解决：
为什么同一个武将在不同岗位价值不同。
为什么扩张需要人才储备。
为什么前线、后方、中枢、战区需要不同类型人物。
为什么官职和身份会限制管理规模。
为什么降将、宗族、士族、旧臣不能只看能力值。
二、岗位层级
建议采用五层岗位：
君主
→ 中枢官职
→ 都督 / 州牧
→ 太守 / 守将
→ 属官 / 县令 / 校尉 / 从事
1. 君主
势力最高决策者。
影响：
势力路线。
外交信誉。
正统和名望。
可任命官职。
中枢容量。
2. 中枢官职
中枢官职负责全势力制度和战略能力。
候选职位：
丞相。
长史。
主簿。
尚书。
军师。
司马。
典农中郎将。
大司农。
太常或礼官。
中枢官职用于承载政令、制度、外交、军制和名分效果。
3. 都督 / 州牧
都督或州牧负责区域战区。
作用：
管理多个城池。
执行区域内政。
指挥战区军备。
提出攻略建议。
负责前线防守和扩张。
4. 太守 / 守将
太守或守将负责单城。
作用：
决定城市基础效率。
推动设施建设。
影响军备和城防。
影响民心和治安。
作为出阵主将候选。
5. 属官 / 县令 / 校尉 / 从事
属官负责细分职能。
职能方向：
农业。
商业。
屯田。
治安。
士族安抚。
军备。
兵器。
马政。
船坞。
谋略。
属官类似《新生》中领主的功能价值，但表达为三国官僚体系。
三、任命原则
1. 能力匹配
岗位应优先匹配能力：
能力
适合岗位
统率
都督、守将、军府、出阵主将
武力
前线将领、战法核心、突击部队
智谋
军师、谋略、计略、战场控制
政治
太守、属官、政令、中枢治理
魅力
招揽、外交、民心、士族安抚
2. 特技匹配
特技决定武将方向。
示例：
屯田型适合粮仓和恢复区。
军制型适合军府和前线。
安抚型适合新占地区。
水军型适合港城。
骑兵型适合北方前线。
谋略型适合边境和军师。
3. 关系匹配
关系会影响稳定性。
考虑：
宗族。
旧主。
同乡。
士族。
姻亲。
宿敌。
派系。
降将不应立即等同于普通家臣。
4. 身份和官职限制
高级岗位需要身份和官职。
限制目的：
防止前期任意配置最优解。
让功绩和升迁有价值。
让组织成长成为系统。
四、治理投射
任命后，武将能力应投射到城市和战区。
1. 城市能力
太守提供城市基础能力。
属官提供补强能力。
建议结构：
城市治理能力
= 太守基础能力
+ 属官职能能力
+ 特技修正
+ 官职修正
+ 政令修正
+ 民心和士族修正
2. 战区能力
都督提供区域能力。
影响：
区域军备。
战区 AI。
多城协同。
补给组织。
前线防御。
攻略提案。
3. 中枢能力
中枢官职提供全势力能力。
影响：
政令成本。
官职容量。
外交效率。
谋略效率。
补给制度。
正统和名望。
五、功绩与升迁
武将通过行为获得功绩。
来源：
治理城市。
建设设施。
提升民心。
完成政令。
战斗胜利。
献策成功。
外交成功。
谋略成功。
功绩用途：
升官。
获得封赏。
解锁高级岗位。
稳定忠诚。
提高名望。
六、忠诚与风险
忠诚受以下因素影响：
君主相性。
官职。
功绩是否被兑现。
赏赐。
旧主存亡。
宗族关系。
政治路线。
民心和正统。
是否长期闲置。
是否被派往危险前线。
低忠诚风险：
出奔。
被策反。
战场倒戈。
治理效率下降。
事件触发。
七、玩家决策
玩家需要判断：
高能力武将放中枢、前线还是地方。
新占城市由本家老臣治理，还是用当地降将安抚。
是否让宗族掌控关键战区。
是否牺牲治理效率换忠诚稳定。
哪些年轻武将需要通过低级岗位培养功绩。
哪些武将适合成为长期都督。
八、AI 行为
AI 任命应遵循：
前线优先统率和武力。
后方优先政治和魅力。
新占地区优先安抚、民心、当地关系。
战区核心优先综合能力和忠诚。
低忠诚武将避免放在独立大军。
亲族和重臣更容易获得高位。
AI 不应只按能力排序。

appointment_slot：岗位槽位表。
appointment_rule：任命规则表。

loyalty_modifier：忠诚修正表。
governance_projection：治理投射规则表。
十、验收标准
本系统可开发时，应能回答：
某武将为什么能或不能担任某岗位。
任命某人为太守后，城市哪些数值发生变化。
属官如何补强太守短板。
都督如何管理战区。
降将为什么忠诚不稳。
功绩如何转化为升迁和封赏。
第 09 章  《三国志：治世与乱世》内政与治世系统
状态：Draft V0.1
阶段：原创企划
用途：定义城市经营、民心、农业、商业、屯田、治安、士族和战后恢复。
一、设计目的
内政系统不是重复点击建设，而是“治世线”的主体。
本系统要解决：
占领的土地如何转化为稳定收益。
为什么文官、安抚型武将和地方士族有价值。
为什么战争会消耗民心和地方秩序。
为什么后方粮仓、商都、军府会支撑前线战争。
为什么扩张太快会带来治理压力。
二、核心资源
内政主要产出和维护：
金钱。
粮草。
兵力。
民心。
治安。
士族支持。
城防。
设施等级。

士族影响。
豪强影响。
设施槽位。

征兵。
征粮。
灾荒。
城池反复易手。
苛政。
屠掠类事件。

治安代表地方秩序。
治安影响：
叛乱概率。
商业效率。
道路安全。
补给稳定。
谋略防御。
治安可由太守、属官、军府、巡查和政策提高。
低治安会导致：

豪强割据。
粮道受扰。
商业下降。

出阵。

农田。

商道。

盐铁或特殊资源。
任命商业属官。
政令加成。
八、屯田
屯田是三国题材的重要治世系统。
屯田作用：
提高粮草产出。
增强前线补给。
安置流民。
提高战区持续作战能力。
屯田代价：
需要政治或军政型人才。
可能占用设施槽。
可能短期降低商业。
在民心低时效果下降。
屯田适合：
中原。
关中。
许昌周边。
前线后方。
新恢复地区。
九、士族与豪强
士族支持代表地方名门合作。
士族支持提高：
人才发现概率。
治理效率。
民心恢复。
商业和文化收益。
新占地区稳定。
士族支持下降：
强行征发。
清洗豪强。
任命外地强硬官员。
政策路线冲突。
豪强影响是地方非中央力量。
豪强过强可能：
降低中央收益。
提高叛乱风险。
影响征兵。
但适度合作可提高地方稳定。

恢复。

周边是否仍有敌军。
十二、玩家决策
玩家需要判断：
是先安民还是先征兵。
是建粮仓还是建军府。
是依赖当地士族还是强行集权。
是把文官放在新占地区还是中枢。
是把后方城市商业化还是军事化。
是短期压榨支持战争，还是长期恢复。
十三、AI 行为
AI 内政应根据城市职责和局势行动：
前线城优先军备、城防、粮草。
后方城优先农业、商业、设施。
新占城优先民心和治安。
港城优先商业和水路。

第 10 章  《三国志：治世与乱世》政令、官制与制度构筑
状态：Draft V0.1
阶段：原创企划
用途：定义政令路线、官制成长、中枢官职、制度维护成本和解锁逻辑。
一、设计目的
制度系统用于把一个军事集团逐步变成国家机器。
本系统要解决：
为什么势力越大越需要制度。
为什么政策不是免费科技树。
为什么文官和中枢职位有长期价值。
为什么不同势力能形成不同玩法流派。
为什么制度扩张会带来财政和政治代价。

制度系统由四部分组成：
政令

五、路线构筑
1. 屯田路线
价值：
粮草高。
远征强。
新占恢复稳定。
代价：
商业增长较慢。
需要政治型人才。
2. 军府路线
价值：
军备速度高。
募兵强。
前线压制强。
代价：
民心压力。
金钱和粮草消耗高。
3. 士族路线
价值：
人才发现。
民心稳定。
地方治理强。
代价：
集权较慢。
部分强硬政策受限。
4. 法治路线
价值：
治安高。
税收稳定。
腐败和叛乱低。

价值：
集权强。

外交警惕。

中枢强则地方可能缺人。

玩家需要判断：

是否用霸府路线快速集权并承受外交风险。
九、AI 行为
AI 应根据势力性格选择制度：
北方强势 AI 倾向军府、马政、霸府。
江东 AI 倾向水军、商业、士族。
巴蜀 AI 倾向屯田、防御、山地补给。
汉室派 AI 倾向正统、士族、民心。
董卓类 AI 倾向霸府和高压，但民心风险高。
AI 不应所有势力走同一政策路线。

第 11 章  《三国志：治世与乱世》武将能力、特技与战法

粮草是否够。
路线是否安全。
敌方援军时间。
是否可形成合围。
是否应撤退。
是否应切断敌方补给。
AI 不应在粮草不足时无脑远征。
十四、数据字段草案
后续至少需要：
army_state：部队动态状态。
army_route_progress：路线进度表。
mobilization_task：整军任务表。
campaign_target：征讨目标表。
food_consumption_rule：粮草消耗规则。
movement_speed_rule：移动速度规则。
supply_network：补给网络表。
army_state_transition：部队状态转换表。
十五、验收标准
本系统可开发时，应能回答：
部队从哪座城生成。
从 A 城到 B 城需要多少时间。
这支部队能在外行动多少天。
粮草不足后状态如何变化。
补给节点如何补粮。
多路部队为什么同时或不同步到达。
AI 为什么撤退、继续围城或转向补给节点。
第 14 章  《三国志：治世与乱世》野战、攻城、关隘与水战
状态：Draft V0.1
阶段：原创企划
用途：定义战斗层规则、战斗类型、地形战、攻城战、关隘战和水路战斗方向。
一、设计目的
战斗系统负责把大地图准备转化为决定性结果。
本系统要解决：
为什么战斗前的行军、粮草、路线和计略会影响胜负。
为什么不同地形需要不同打法。
为什么攻城和野战不是同一种战斗。
为什么关隘和水路能形成三国特色。
为什么关键战斗能形成声势，改变周边局势。
二、战斗类型
首版建议战斗类型：
大地图接触战。
野战 / 会战。
攻城战。
关隘战。
港口战。
水路遭遇战。
水战首版可先简化为水路和港口相关战斗，不必立即制作完整独立大型水战系统。
三、大地图接触战
接触战发生在部队行军途中。
用途：
表现遭遇、截击、追击。
决定是否进入会战。
消耗兵力和士气。
阻止敌军救援。
接触战应受：
部队速度。
路线。
地形。
主将能力。
士气。
是否缺粮。
伏兵或伪报影响。
四、野战 / 会战
野战是玩家主动介入的重要战斗。
核心元素：
战场地形。
要点。
士气。
阵型。
夹击。
战法。
军师计略。
退路。
总大将。
胜负不应只由兵力归零决定，也可以由士气崩溃、总大将败退、退路被断等决定。
五、战场要点
要点是战斗地图上的关键位置。
作用：
提高士气。
控制路线。
形成夹击。
保护退路。
支撑火攻或伏兵。
要点设计应与大地图地形相关。
六、士气
士气代表部队战斗意志。
士气受：
整军完成度。
主将统率。
军师。
民心和名望。
是否缺粮。
要点占领。
夹击。
战法。
伤亡。
退路。
士气崩溃可导致撤退或溃散。
七、攻城战
攻城战发生在攻击城池或重镇时。
核心对象：
城墙。
城门。
城内据点。
守军。
攻城器械。
防御设施。
粮草。
援军。
攻城战前置：
攻方是否有足够粮草。
是否准备攻城器械。
是否切断援军。
是否先进行谋略。
守方城防和民心。
攻城不应只是更慢的野战，而是围绕时间、粮草、援军、城防的消耗战。
八、关隘战
关隘战是三国地理特色。
特点：
攻方展开受限。
守方防御优势高。
粮草压力大。
绕路价值高。
攻破后可打开战略通道。
关隘战适合表现：
关中。
汉中。
巴蜀。
荆襄山道。
北方边塞。
九、港口战和水路战
首版建议水战简化但保留战略价值。
港口战作用：
控制水路补给。
支撑江河机动。
切断敌方沿江援军。
形成水陆夹击。
水路战影响：
船只。
水军适性。
风向或水流简化修正。
港口设施。
沿岸支援。
后续可扩展为完整水战模式。
十、军师计略
军师在战斗中提供：
识破伏兵。
降低敌方士气。
制造混乱。
火攻。
诱敌。
保护退路。
提高战法效率。
军师不是单独替代主将，而是与主将形成组合。
十一、战斗结果
战斗结果包括：
胜利。
败退。
溃散。
俘虏。
城池占领。
声势形成。
武将功绩。
民心变化。
敌方援军延迟。
战斗结果必须回流大地图。
十二、玩家决策
玩家需要判断：
是否主动进入会战。
是否绕过重镇。
是否先切断援军。
是否在粮草不足前撤退。
是否强攻城池。
是否抢占要点。
是否用战法追求大胜声势。
是否在水路展开侧翼。
十三、AI 行为
AI 战斗判断：
是否接受会战。
是否守城拖延。
是否撤退保存兵力。
是否救援。
是否利用关隘。
是否追击缺粮敌军。
是否避开敌方主力。
AI 不应每次都无脑决战。
十四、数据字段草案
后续至少需要：
battle_type：战斗类型表。
battle_state：战斗状态表。
battlefield_point：战场要点表。
morale_rule：士气规则表。
siege_rule：攻城规则表。
pass_battle_rule：关隘战规则表。
port_battle_rule：港口战规则表。
battle_result_effect：战斗结果效果表。
十五、验收标准
本系统可开发时，应能回答：
什么情况下触发接触战、会战、攻城或关隘战。
士气如何变化。
缺粮如何影响战斗。
攻城为什么需要粮草和器械。
关隘为什么难攻。
战斗结果如何影响声势和大地图。
第 15 章  《三国志：治世与乱世》声势、归附与战后整合
状态：Draft V0.1
阶段：原创企划
用途：定义关键胜利扩散、敌城动摇、地方归附、降将安置和新占治理。
一、设计目的
战斗胜利不应只带来单场兵力变化。
本系统要解决：
为什么关键战役能改变一片地区的局势。
为什么敌城会因大败动摇。
为什么豪强、降将和地方士族会重新站队。
为什么战后必须重新任命和治理。
为什么连续扩张会带来整合压力。
二、声势系统
声势代表一场大胜带来的地区震慑和归附效应。
触发来源：
野战大胜。
攻破重镇。
击败名将。
夺取关隘。
占领州治。
斩断敌方粮道。
完成阶段目标。
声势影响：
周边敌城动摇。
敌方民心下降。
地方豪强归附。
敌将劝降成功率提高。
我方名望提高。
盟友和中立势力态度变化。
三、声势强度
声势强度可由以下因素计算：
战斗规模。
敌我兵力差。
是否击败总大将。
是否攻破重镇。
是否控制战略节点。
我方君主名望。
主将特技。
敌方民心和忠诚。
声势范围受：
地理距离。
道路连接。
同州同郡。
敌方补给链。
地方士族关系。
四、敌城动摇
敌城受到声势影响后可能进入：
稳定。
动摇。
恐慌。
可劝降。
自动归附。
影响因素：
城防。
守将忠诚。
粮草。
民心。
援军距离。
旧主关系。
我方名望和正统。
五、地方归附
地方归附对象包括：
豪强。
士族。
中立小城。
敌方边境城。
降将集团。
归附不是免费收益。
归附后需要：
任命官员。
确认忠诚。
处理原有关系。
安抚民心。
维持治安。
六、战后接收
战后接收内容：
城池。
人口。
粮草。
金钱。
设施。
俘虏。
降将。
地方关系。
不同接收方式影响不同：
强攻占领：城防损坏、民心下降。
劝降归附：设施较完整、降将忠诚需观察。
声势倒戈：接收快，但地方派系复杂。
七、降将安置
降将需要安置策略。
安置方式：
留任原地。
调离故地。
放入中枢观察。
编入前线。
闲置。
封赏安抚。
不同方式影响：
忠诚。
地方稳定。
旧臣不满。
人才利用效率。
策反风险。
八、新占治理
新占地区应进入恢复状态。
恢复状态和内政系统相连：
动荡
→ 接管
→ 恢复
→ 稳定
→ 繁荣
玩家需要：
任命太守。
配置属官。
恢复民心。
稳定士族。
修复城防。
判断城市职责。
九、战后封赏
战后需要处理功绩。
封赏方式：
升官。
赐爵。
赏金。
赐宝。
任命新职。
授予封邑。
不封赏后果：
忠诚下降。
功臣不满。
派系不稳。
后续出战积极性下降。
十、玩家决策
玩家需要判断：
是追求声势大胜，还是稳妥占领。
是否劝降敌城。
降将留任还是调走。
新占城先恢复还是军事化。
是马上继续进攻，还是停下来整合。
战功如何分配避免内部分裂。
十一、AI 行为
AI 应能：
判断声势影响下是否守城或投降。
大败后转入防守或求和。
对新占地区优先治理。
封赏功臣。
防范低忠诚降将。
利用己方大胜扩大劝降。
十二、数据字段草案
后续至少需要：
momentum_event：声势事件表。
momentum_rule：声势规则表。
city_shaken_state：城池动摇状态表。
defection_event：归附事件表。
postwar_integration：战后整合表。
surrendered_officer_state：降将状态表。
reward_action：封赏行为表。
十三、验收标准
本系统可开发时，应能回答：
什么样的胜利能触发声势。
声势影响哪些城和哪些人物。
敌城为什么动摇或归附。
强攻和劝降接收有何差异。
降将如何安置。
战后不整合会出现什么风险。
第 16 章  《三国志：治世与乱世》都督府、委任与 AI
状态：Draft V0.1
阶段：原创企划
用途：定义大势力后期管理、战区委任、都督府行为、家臣献策和 AI 沙盘行为。
一、设计目的
当势力扩大后，玩家不应继续逐城手动操作所有事务。
本系统要解决：
大势力后期如何降低管理压力。
多战区如何同时运转。
都督和地方官如何体现主动性。
AI 势力如何在同一套规则下扩张、治理、外交和作战。
玩家如何既能委任，又能保持战略控制。
二、都督府定位
都督府是区域战区管理单位。
结构：
君主
→ 中枢
→ 都督府
→ 城池
→ 太守 / 属官 / 部队
都督府负责：
区域内政。
区域军备。
前线防守。
征讨提案。
多城协同。
补给组织。
战后接收。
三、设立条件
设立都督府需要：
官制达到等级。
拥有一定城池。
有合适都督人选。
有区域核心城。
金钱或维护成本。
都督人选要求：
较高身份或官职。
统率、政治或综合能力达标。
忠诚稳定。
适合区域地形和战略方向。
四、都督府范围
都督府范围由城市和路线组成。
划分原则：
地理连贯。
补给顺畅。
前线明确。
后方支撑。
不跨越过多无关战区。
范围过大可能导致效率下降。
五、委任权限
玩家可设置都督府策略。
策略类型：
内政优先。
防守优先。
攻略优先。
补给建设。
新占恢复。
军备积累。
牵制作战。
都督府可以自动：
任命低级属官。
建设符合职责的设施。
整军。
出阵。
防守。
请求援助。
提出征讨建议。
高级任命、称王称帝、中枢政令等仍由玩家决定。
六、献策系统
家臣和都督应主动提出建议。
献策类型：
建设设施。
调整城市职责。
任命或调任。
征讨目标。
防守提醒。
外交建议。
谋略建议。
封赏提醒。
新占治理。
献策价值：
降低信息负担。
提醒玩家风险。
让武将显得主动。
给 AI 判断可解释性。
七、AI 层级
AI 分为六层：
势力 AI
→ 战略区 AI
→ 城市 AI
→ 人事 AI
→ 军事 AI
→ 战斗 AI
1. 势力 AI
判断：
扩张方向。
外交策略。
政令路线。
汉室态度。
称王称帝时机。
是否设立都督府。
2. 战略区 AI
判断：
哪些城是前线。
哪些路线可进攻。
哪些补给节点重要。
是否需要防守或牵制。
3. 城市 AI
判断：
城市职责。
设施建设。
民心恢复。
军备。
粮草储备。
4. 人事 AI
判断：
太守。
属官。
都督。
中枢官职。
出阵武将。
降将安置。
5. 军事 AI
判断：
征讨目标。
出阵城。
路线。
粮草是否足够。
是否协同。
是否撤退。
6. 战斗 AI
判断：
是否进入会战。
是否守城。
是否追击。
是否抢要点。
战法时机。
是否保存兵力。
八、AI 性格
AI 势力应有性格参数。
维度：
扩张性。
保守性。
外交倾向。
名分倾向。
军事偏好。
内政偏好。
冒险度。
背盟倾向。
任人唯亲倾向。
性格影响行为，但不能覆盖基本理性。
九、AI 与玩家同规则
原则：
AI 尽量使用和玩家相同的系统对象。
AI 也应受：
粮草。
行军时间。
补给。
民心。
忠诚。
政令维护。
官职容量。
可以为难度提供修正，但不能破坏核心规则认知。
十、玩家决策
玩家需要判断：
哪些地区委任给都督。
给都督什么战略方针。
是否批准都督献策。
是否收回战区权限。
是否把强将放都督府还是中央。
是否信任高能力但低忠诚的都督。
十一、数据字段草案
后续至少需要：
governorate：都督府表。
governorate_city：都督府城市关联。
governorate_policy：都督府方针。

十二、验收标准
本系统可开发时，应能回答：
什么时候能设立都督府。
都督府能自动做哪些事，不能做哪些事。
AI 为什么选择某个目标。
AI 是否会考虑粮草和路线。
献策为什么出现。
玩家如何调整委任方针。

第 18 章  《三国志：治世与乱世》MVP 范围与开发验收
状态：Draft V0.1
阶段：原创企划
用途：定义首版可玩范围、系统优先级、验收标准和后续开发需求文档转化方向。
一、设计目的
大型历史战略游戏不能一开始就做完整商业版规模。
MVP 的目标不是内容完整，也不是从零验证玩法是否好玩。
本项目的核心玩法框架参考成熟竞品，玩法方向已经被市场证明。MVP 需要验证的是：
三国化适配是否顺畅。
工程实现是否可控。
数值节奏是否符合三国地图和势力规模。
UI 是否能解释复杂信息。
AI 是否能在同规则下形成压力。
MVP 应跑通以下核心链路：
任命
→ 治理
→ 政令
→ 整军
→ 出阵
→ 行军
→ 战斗
→ 声势
→ 战后整合
如果这条链路在三国化后不顺畅，再多武将、事件和美术都会被系统摩擦抵消。
二、MVP 必须验证的适配点
MVP 必须确认：
城池职责不同。
任命不同武将会改变城市和战区表现。
部队从城池出阵。
部队携带粮草。
大地图移动需要时间。
路线和补给影响战争。
战斗胜利能影响地区局势。
战后需要治理。
政令有维护成本和路线取舍。
AI 能在同一张地图上扩张和防守。

城市职责。
简化政令。

基础攻城。

基础 AI 扩张。

谋略。

特技和战法。

六、核心验收用例
1. 任命验收
场景：
同一座城分别任命政治高武将和统率高武将为太守。
预期：
政治高武将提高内政发展。
统率高武将提高军备和防守。
UI 能显示差异来源。
2. 出阵验收
场景：
从 A 城出阵 5000 兵。
预期：
A 城兵力减少。
生成部队对象。
部队绑定 A 城。
部队拥有随军粮草。
3. 行军验收
场景：
部队沿道路从 A 城到 B 城。
预期：
部队按时间推进。
到达时间与路线距离和速度一致。
行军期间消耗粮草。
4. 缺粮验收
场景：
部队粮草不足继续远征。
预期：
进入缺粮状态。
士气下降。
移动速度下降。
战斗力下降。
5. 补给验收
场景：
部队经过友方补给节点。
预期：
部队粮草恢复或消耗降低。
补给节点资源减少或进入冷却。
6. 攻城验收
场景：
攻击有城防和守军的敌城。
预期：
攻城消耗时间和粮草。
守军和城防影响攻城结果。
粮草不足会降低攻城效率。
7. 声势验收
场景：
玩家以优势战果击败敌主力并夺取重镇。
预期：
周边敌城进入动摇状态。
我方名望上升。
劝降概率提高。
8. 战后整合验收
场景：
占领一座民心低的新城。
预期：
新城收益下降。
需要任命太守恢复。
若忽视治理，治安下降或叛乱风险上升。
9. 政令验收
场景：
开启一条有月维护费的政令。
预期：
每月扣除金钱。
金钱不足时政令暂停或降级。
效果在 UI 和数值上可检查。
10. AI 验收
场景：
AI 有两个可攻击目标，一个近且补给充足，一个远且粮草不足。
预期：
AI 优先选择近且可执行的目标。
AI 不应频繁派兵进行无补给远征。

第 19 章  《三国志：治世与乱世》系统企划案总装版
状态：Draft V0.1
阶段：系统企划总装
用途：把当前分章企划整理成一份团队可评审的总览文档。
说明：本文是总装索引和高层摘要，详细规则以对应章节为准。
一、项目定义
《三国志：治世与乱世》是一款三国题材大型单机历史战略游戏。
玩家扮演汉末三国时代的一方势力之主，通过任命人才、治理州郡、建设制度、经营名分、筹粮整军、指挥战役和整合新领土，在乱世中扩张势力，并最终建立新的天下秩序。
一句话核心：
以人为本，以城为基，以粮为限，以势破局，以制度定天下。
二、设计边界
本项目参考《信长之野望：新生 / 威力加强版》的核心策略骨架，但不直接复刻其系统命名、文本、数据、UI、美术和数值。
保留的是：
人事驱动经营。
城市职责化。
政策 / 制度长期构筑。
武将技能和岗位组合。
战前整军、行军、粮草和补给。
关键战役改变地区局势。
大势力后期委任和 AI 沙盘。
重构的是：
三国题材制度。
汉室正统。
州郡治理。
士族与豪强。
宗族、旧主、姻亲和降将关系。
关隘、水路、渡口和粮道。
军师谋略。
声势、归附和战后整合。
三、核心循环
主循环：
观察天下大势
→ 调整人事与战区
→ 治理州郡与城市职责
→ 颁行政令与经营名分
→ 设定征讨或外交目标
→ 筹粮、募兵、整军、计略
→ 出阵、行军、补给、接敌
→ 野战、攻城、关隘战或水陆战
→ 形成声势、占领、归附或停战
→ 封赏、升迁、安置降将、恢复民心
→ 重组领土和战区
→ 进入下一轮治世与乱世循环
三段体验：
治世准备：把土地、人才和制度转化为长期能力。
乱世突破：把粮草、军备、路线和谋略转化为战争成果。
战后整合：把占领、归附和降将转化为稳定收益。

5. 战役
包括征讨目标、整军、出阵、行军、补给、野战、攻城、关隘战、水路战和声势扩散。

三、军事链路联动
城市职责
→ 整军效率
→ 出阵部队
→ 随军粮草
→ 行军时间
→ 接敌 / 围城
→ 战斗结果
→ 声势
→ 战后整合
→ 新城市职责
关键检查点：
城市必须能提供兵力和粮草。
道路必须能计算移动时间。
部队必须有状态。
粮草必须影响行军和战斗。
战斗必须回流到地图和城市状态。
四、人事链路联动
武将能力和特技
→ 岗位任命
→ 城市 / 战区 / 中枢效果
→ 功绩获得
→ 升迁和封赏
→ 解锁更高岗位
→ 承担更大责任
关键检查点：
岗位不能只看能力总和。
特技必须有岗位触发范围。
功绩必须回流忠诚和升迁。
降将必须有观察和稳定过程。
五、治世链路联动
太守和属官
→ 民心、治安、农业、商业、屯田
→ 金钱、粮草、兵力
→ 政令维护和出阵能力
→ 战争消耗
→ 新占地区恢复
关键检查点：
民心不只是显示值，必须影响收益和风险。
士族支持必须影响地方稳定和人才。
屯田必须和粮草、补给、远征关联。
六、制度链路联动
名望 / 正统 / 金钱 / 文官
→ 政令和官制
→ 岗位容量、统治范围、制度效果
→ 更高效率治理和战争
→ 更大领土
→ 更高维护成本
关键检查点：
政令必须有维护成本。
金钱不足要导致暂停或降级。
官制要影响都督府和岗位容量。
制度不能成为无脑全开科技树。
七、声势链路联动
关键战役
→ 声势强度
→ 周边城池动摇
→ 劝降和归附
→ 降将和新占地区
→ 战后整合
→ 名望提升
关键检查点：
声势范围必须受地理和道路影响。
声势不是免费吞城，归附后仍需治理。
声势应影响外交态度和劝降成功率。
八、AI 联动要求
AI 必须至少理解：
地图距离。
粮草是否足够。
补给节点价值。
城市职责。
武将岗位适性。
外交风险。
战后治理压力。
AI 不应只根据兵力比决定出兵。

AI 系统 → 所有可执行行为。

四、示例：出阵行军补给需求拆法
来自企划：
部队从城池出阵，携带随军粮草，在大地图移动，移动消耗时间和粮草，缺粮后速度、士气和战斗力下降。
转开发需求：
玩家从城市界面选择出阵。
系统校验可用兵力、武将状态、粮草储备。
出阵后生成 state_army。
state_army.origin_city_id 绑定出阵城。
城市可用兵力减少。
部队获得 food_current 和 food_capacity。
部队选择路线后进入 marching 状态。
每个时间 tick 更新 route_progress。
每个时间 tick 根据规则扣除粮草。
粮草为 0 后进入 out_of_supply 或 缺粮 状态。
缺粮状态修改移动速度、士气和战斗力。
到达目标后进入接敌、围城、攻城或归城状态。
验收：
从 A 城到 B 城的移动时间与路线距离和速度一致。
出阵后 A 城兵力减少。
粮草不足时按预期进入缺粮状态。
经过补给节点时粮草恢复或消耗降低。
五、示例：任命系统需求拆法
来自企划：
玩家任命太守、属官、都督和中枢官职，让武将能力和特技投射到城市、战区和制度。
转开发需求：
系统读取 master_officer 和 state_officer。
系统读取岗位规则 rule_appointment。
玩家打开任命界面。
系统列出可任命武将。
不满足身份、位置、忠诚或状态条件的武将不可选。
任命后写入对应岗位状态。
城市、战区或势力重新计算效果。
UI 显示任命前后差异。
验收：
不符合条件武将无法任命。
任命政治高太守后城市内政效率提高。
任命统率高都督后战区军备和协同提高。

第 24 章  《三国志：治世与乱世》时间系统与结算规则
状态：Draft V0.1
阶段：总装补充
用途：统一月度政略、日级行军、战斗时间和结算顺序。
一、设计目的
本项目同时存在长期经营和大地图行军。
因此时间系统必须同时支持：
月度内政结算。
政令维护。
城市发展。
谋略和外交进度。
整军进度。
部队在大地图按时间移动。
行军和作战粮草消耗。
战斗触发和战后结算。
如果时间规则不统一，程序、数值和 UI 会很容易出现矛盾。
二、推荐时间层级
建议采用三层：
年
→ 月
→ 日 / 时间 tick
1. 年
用于：
剧本年份。
武将年龄。
历史事件。
年度统计。
阶段目标。
2. 月
月是主要政略结算单位。
用于：
金钱收入。
粮草收入。
政令维护费。
城市发展进度。
民心和治安变化。
武将功绩结算。
外交和谋略推进。
AI 势力战略判断。
3. 日 / 时间 tick
日或时间 tick 用于大地图动态行为。
用于：
部队移动。
随军粮草消耗。
整军进度。
围城进度。
接敌检测。
援军抵达。
三、月度结算顺序
建议月初按以下顺序结算：
1. 时间推进到新月
2. 城市收入结算
3. 粮草收入结算
4. 政令维护费扣除
5. 政令暂停或恢复判断
6. 城市发展和设施进度
7. 民心、治安、士族状态变化
8. 武将功绩和忠诚变化
9. 外交、谋略、献策进度
10. AI 战略判断
11. UI 汇总提示
注意：
政令维护费在收入后扣除，避免月初现金流过于惩罚。
如果后续希望更硬核，可改为月初先扣费，但必须全局统一。
当前建议采用收入后扣费，便于玩家理解。
四、日级行军结算顺序
每个日级 tick 建议：
1. 更新部队路线进度
2. 计算行军粮草消耗
3. 检查补给节点
4. 检查缺粮状态
5. 检查接敌
6. 检查抵达目标
7. 更新 UI
8. AI 微决策
五、战斗结算顺序
战斗结束时：
1. 计算胜负
2. 计算伤亡
3. 更新部队状态
4. 更新武将状态和功绩
5. 更新城池或节点控制
6. 判断是否触发声势
7. 生成俘虏、降将或归附事件
8. 进入战后整合
9. UI 战报
六、整军和任务进度
整军、谋略、外交、建设等任务都应有进度。
建议字段：
current_progress。
required_progress。
progress_per_tick。
status。
任务可按月或日推进，但必须标明。
示例：
城市设施：按月推进。
政令准备：按日或月推进均可，建议按日以便显示剩余天数。
整军：按日推进。
谋略：按日推进。
七、暂停与倍速
如果游戏采用实时暂停或半即时大地图，应支持：
暂停。
低速。
中速。
高速。
暂停时：
UI 可操作。
时间不推进。
部队不移动。
任务不结算。
八、玩家信息反馈
玩家需要清楚看到：
当前年月。
距离下次月度结算还有多久。
政令每月维护费。
部队预计抵达时间。
部队剩余粮草天数。
建设、整军、谋略剩余时间。
月度结算摘要。
九、AI 结算
AI 不应每个 tick 做重型全局计算。
建议：
月度做势力战略判断。
日级做局部行军、接敌、撤退判断。
战斗结束后做即时反应。
声势事件后做局部外交和防守判断。
十、开发需求转化提示
后续应转化为：
DEV_时间推进_月度结算_任务进度需求说明.md
该开发文档需要明确：
时间数据结构。
tick 频率。
月度结算顺序。
暂停和倍速。
AI 更新频率。
UI 提示。

第 27 章  《三国志：治世与乱世》胜利条件、终局与结局路线
状态：Draft V0.1
阶段：完整理论设计
用途：定义游戏如何从乱世走向终局，玩家怎样获胜，以及不同路线如何结算。
一、设计目的
大型历史战略游戏最容易出现的问题是：
中盘已经无敌，但还要机械推完所有城。
本系统要解决：
统一是否必须占领所有城。
后期如何避免无聊扫图。
称王、称帝、复汉、禅让、统一如何形成路线差异。
玩家不同玩法如何得到不同结局评价。
胜利不仅是军事胜利，也包括政治秩序建立。
二、胜利设计原则
1. 统一不只等于全地图占领
标准胜利应包含：
控制核心州郡。
消灭、臣服或从属主要敌对势力。
拥有足够名望。
拥有足够正统或完成替代正统路线。
核心领土稳定。
财政和民心不崩溃。
2. 后期允许政治收束
当玩家已形成压倒性大势，游戏应允许通过：
劝降。
臣服。
禅让。
天下承认。
声势扩散。
最终决战。
来加速终局，而不是强迫玩家清扫每座边远小城。
3. 路线决定结局
玩家可以通过不同方式完成天下：
复兴汉室。
禅让建国。
自立称帝。
霸府摄政。
诸侯共主。
军事征服。
每条路线的条件、风险和结局评价不同。
三、胜利类型
1. 军事统一
条件方向：
控制绝大多数核心城池。
主要敌对势力灭亡或臣服。
玩家拥有最高军事实力。
特点：
最直接。
对正统要求较低。
战后民心和士族压力较高。
2. 正统统一
条件方向：
控制天子或完成汉室路线。
正统达到高阈值。
多数势力承认玩家。
核心州郡稳定。
特点：
外交和名分收益高。
对恶政和背盟更敏感。
3. 禅让建国
条件方向：
控制天子。
名望和正统达到阈值。
拥有压倒性势力。
中枢官制成熟。
主要反对势力被压制。
特点：
合法性较高。
适合曹魏式路线。
4. 复兴汉室
条件方向：
君主路线支持汉室。
拥有足够正统。
消灭主要篡逆势力。
恢复核心州郡秩序。
特点：
对忠汉派武将有强吸引力。
称帝路线受限。
5. 霸府摄政
条件方向：
控制天子。
不称帝。
主要诸侯臣服。
中枢制度成熟。
特点：
可长期保持汉室名义。
内部权臣风险和正统争议并存。
6. 地区霸权结局
非标准小胜利。
条件方向：
控制一个大区域。
完成势力特色目标。
在限定年限内存续并强盛。
用途：
给小势力、挑战剧本、短剧本提供阶段结算。
四、终局阶段
建议游戏进入终局阶段的条件：
玩家控制核心州郡达到阈值。
玩家名望达到高阈值。
最大敌对势力被击败或衰弱。
玩家可称王、称帝或迫使诸侯臣服。
终局阶段解锁：
天下檄文。
最终讨伐。
大规模劝降。
禅让路线。
称帝路线。
诸侯臣服谈判。
五、终局压力
玩家接近胜利时，系统仍应提供压力：
反玩家联盟。
忠汉派或反篡逆势力不满。
新占地区治理压力。
大规模军费和政令维护。
降将与地方士族稳定问题。
边远地区叛乱。
但压力应是最后考验，不应拖成长时间重复劳动。

统一方式。
用时。
民心。
正统。
名望。
战争伤亡。
叛乱次数。
降将安置。
经济繁荣。
文化或士族支持。
评价称号示例：

乱世霸主。
中兴之主。
铁血征服者。
名分共主。
权臣摄政。
七、玩家决策
玩家需要判断：
是尽快称帝，还是积累正统。
是军事扫平，还是劝降臣服。
是复汉，还是自立。
是否接受附庸保留。
是否为了快速胜利承受民心和正统代价。
八、AI 行为
AI 在终局阶段应：
判断是否臣服。
判断是否加入反玩家联盟。
判断是否求和。
判断是否继续死守。
对高声势玩家更容易动摇。
AI 不应在明显无望时全部无条件死战。

第 34 章  《三国志：治世与乱世》项目风险与制作管理
状态：Draft V0.1
阶段：完整理论设计
用途：识别大型历史战略游戏的主要制作风险，并提出管理策略。
一、设计目的
大型单机历史战略游戏的风险不只在程序难度，也在范围失控、数据量失控、系统互相打架和团队协作失控。
本章要解决：
哪些风险最可能导致项目失败。
如何提前控制。
团队协作时如何避免返工。
哪些内容必须先做适配和工程确认。
二、主要风险
1. 范围失控
表现：
想一次性做完整三国。
过早做全量武将。
过早做全量剧本。
系统不断加新玩法。
控制：
先技术原型。
再 MVP。
地图和武将库后置专项。
所有新系统必须回到核心循环。
2. 数据量失控
表现：
表格字段未定就开始填大量数据。
多人填表格式不统一。
技能和政策重复。
控制：
先完成数据母表。
统一字段字典。
建立枚举值。
做数据检查工具。
3. 成熟玩法框架在三国化后失真
表现：
三国化系统只换名字，没有形成汉室、士族、关隘、水路等题材差异。
行军粮草虽然存在，但地图尺度不适配。
战后整合过重，打断成熟扩张节奏。
控制：
用小地图做三国化适配测试。
记录扩张速度、粮草压力和战后恢复时间。
观察玩家是否能理解三国化新增压力。
UI 必须解释系统。
4. AI 不可信
表现：
AI 无脑送兵。
AI 无视粮草。
AI 不会防守。
AI 作弊感太强。
控制：
AI 必须先理解地图、粮草、补给。
难度修正不能破坏底层规则。
小地图反复测试。
5. UI 信息爆炸
表现：
玩家看不懂为什么输。
出阵前不知道会缺粮。
任命前不知道效果。
控制：
UI 信息架构先行。
行动确认界面必须显示成本、时间、风险。
战后结算必须解释结果。
6. 团队协作混乱
表现：
多人改同一文件。
同一系统多个名字。
文档和数据表脱节。
控制：
使用协作任务板。
使用术语表。
修改母版前先记录。
每份 DEV 文档引用来源企划。
三、关键确认点
项目早期必须确认：
城市出阵是否顺。
行军时间是否适配三国地图尺度。
粮草是否能合理限制远征。
补给节点是否有争夺价值。
任命是否改变城市表现。
战后整合是否有压力但不过度打断节奏。
AI 是否会考虑粮草。

二、核心结论

本轮未发现以下硬性矛盾：
未发现把部队设计成瞬移到战场的描述。

三、已固定的一致性原则
1. 军事底层原则
当前所有军事相关章节保持一致：
城池提供部队
→ 部队绑定出阵城
→ 部队携带随军粮草
→ 大地图移动需要时间
→ 移动速度受路线、地形、状态、部队规模等影响
→ 行军和作战消耗粮草
→ 补给节点支撑远征
→ 缺粮影响速度、士气和战斗力
该原则后续转开发需求文档时必须保留。
2. 地图与武将库边界
当前企划案只定义：
地图层级。
城池和节点类型。
道路、水路、粮道规则。
武将能力字段。
岗位和关系结构。
当前企划案不定义：
最终城池数量。
最终城池名单。
最终武将数量。
最终武将名单。
全剧本初始归属。
这些内容后续单独作为地图库和武将库专项完成。
3. 技能系统边界
当前技能系统原则：
保留《新生》式底层功能结构。
不直接沿用原作独有名称和文本表达。
改为三国题材技能名、背景和效果描述。
额外增加军师协同、关系触发、地形专长、声势连锁等创新。
后续技能表应包含功能映射字段，便于追踪哪些是保留功能、哪些是新增机制。
4. 原作术语替换原则
当前正式系统名采用：
知行 → 州郡治理 / 封邑 / 属地。
城主 → 太守 / 守将。
领主 → 属官 / 县令 / 校尉 / 从事。
家宰 / 奉行 → 中枢官职 / 府署。
威风 → 声势 / 震慑 / 归附。
大名 → 君主 / 诸侯 / 权臣 / 皇帝。
原作术语只允许在竞品映射和差异说明中出现。
